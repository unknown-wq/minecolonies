# PORT-GAPS — что отключено, деградировано или не проверено

Рабочий список на «потом». Заполняется агентами по ходу порта, по строке на каждый срез.
Правило заказчика: **зелёная сборка важнее полноты фич, но всё вырезанное должно быть
записано так, чтобы это можно было починить, не занимаясь археологией.**

Каждой строке здесь обязан соответствовать маркер в коде:
```java
// TODO(port-26.2): DISABLED — <причина одной строкой>
/* … оригинальный код нетронутым … */
```
Сверка перед сдачей: `grep -rn "TODO(port-26.2)" src | wc -l` == числу строк в таблицах ниже.

Колонки:
- **Что видно в игре** — наблюдаемое следствие. Если следствия нет, так и писать («невидимо»).
- **Как чинить** — конкретная зацепка: какой класс, какой API 26.2, что проверить.
- **Приоритет** — 🔴 серверный геймплей · 🟡 клиентская визуалка · 🟢 совместимость/косметика.

## Разделение `src/main/resources` и `src/main/generated` (готовый рецепт)

Список `26.2/DATAGEN-OWNED-FILES.txt` — это **точное пересечение** оракула
`26.1/src/datagen/generated/domum_ornamentum/` с `26.2/src/main/resources/`: 746 файлов, все 746
подтверждённо существуют. Оракул при этом строгое подмножество ресурсов (файлов, которые есть в
оракуле и которых нет в ресурсах, — ноль), поэтому список полный и точный.

```sh
cd /home/user/Domum-Ornamentum/26.2
# перепроверить, что список всё ещё сходится с оракулом:
diff <(sort DATAGEN-OWNED-FILES.txt) \
     <(comm -12 <(cd ../26.1/src/datagen/generated/domum_ornamentum && find . -type f | sort) \
                <(cd src/main/resources && find . -type f | sort))
# удалить:
(cd src/main/resources && xargs -a ../../../DATAGEN-OWNED-FILES.txt rm -f)
find src/main/resources -type d -empty -delete
```

Что **остаётся** в `src/main/resources` после этого — 267 файлов, и все они рукописные:

| | сколько | что |
|---|---|---|
| `assets/…/models/**/*_spec.json` | 198 | родители кастомного модель-лоадера; датаген на них только ссылается |
| `assets/…/models/block/{architectscutter,barrel_dec/*,timber_frame/dynamic_timberframe_item}.json` | 4 | не генерируются |
| `assets/…/models/item/{architectscutter,blockbarreldeco_onside,blockbarreldeco_standing}.json` | 3 | не генерируются |
| `assets/…/blockstates/{architectscutter,blockbarreldeco_onside,blockbarreldeco_standing}.json` | 3 | не генерируются |
| `assets/…/textures/**`, `assets/minecraft/textures/**` | 57 | текстуры |
| `fabric.mod.json`, `domum_ornamentum.mixins.json` | 2 | конфиги |

**Цена решения — сознательная и обратимая:** контракт C8 («мод укомплектован контентом при красном
датагене») после удаления перестаёт действовать, `src/main/generated` становится обязательным входом
сборки. Ровно так это и устроено в референсном `/workspace/desolation` — там `src/main/generated`
**закоммичен** в git и в `build.gradle:137-142` стоит явная проверка, что каталог на месте
(«restore it with `git checkout -- src/main/generated`»). Рекомендую скопировать оттуда и проверку,
и практику коммита сгенерированного пака.
